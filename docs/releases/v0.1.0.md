# v0.1.0

Draft release notes for the first `mc-router` MVP release.

`mc-router` provides `mc-gateway`, a lightweight Minecraft Java Edition TCP gateway that routes one public listener to backend Minecraft servers based on the hostname in the initial Minecraft handshake. It is designed for static YAML routing first, with namespace-scoped Kubernetes Service annotation discovery available for containerized deployments.

## Highlights

- Go single binary named `mc-gateway`.
- Static YAML route configuration.
- Minecraft Java Edition handshake-based routing using requested `serverAddress`.
- TCP backend proxying that forwards the original handshake bytes.
- Unknown host policy with `deny` and `default` modes.
- Optional status ping fallback response for denied routes and backend status dial failures.
- Optional login disconnect fallback response for denied login starts.
- Optional Prometheus metrics endpoint.
- Graceful shutdown on SIGINT/SIGTERM.
- `SIGHUP` config reload for route changes on supported platforms.
- Namespace-scoped Kubernetes Service annotation discovery.

## Kubernetes Discovery

v0.1.0 includes namespace-scoped Kubernetes Service annotation discovery. It does not support all-namespaces discovery, Pod annotation discovery, EndpointSlice discovery, or CRD route discovery.

Included Kubernetes discovery behavior:

- Startup initial Service list when `discovery.kubernetes.enabled: true`.
- `SIGHUP` reload Service re-list using the startup discovery namespace, annotation prefix, and client setup.
- Runtime Service watch updates that apply complete replacement discovery results.
- Retry/backoff recovery for runtime watch failures.
- Route-only provider boundaries: `RouteProvider`, Kubernetes `SnapshotProvider`, and `RouteSnapshot` carry route data only.
- Low-cardinality discovery metrics, including skipped Service counts by bounded reason.
- Failure preservation: failed startup discovery fails startup; failed reload discovery preserves the previous active route snapshot and skipped Service gauges; failed runtime watch rebuilds preserve the previous active snapshot.

Discovery is Service-based. Backends are generated as Kubernetes Service DNS names in the form `service.namespace.svc.cluster.local:port` after annotations and Service ports validate.

## Reload Behavior

`SIGHUP` reload reads the static config file and applies a new route snapshot only after validation and rebuild succeed. Active connections keep the snapshot they loaded when they started; new connections use the latest successful snapshot.

When Kubernetes discovery was enabled at startup, reload also performs a fresh Service list and rebuilds discovered routes through the same `BuildDiscoveredRoutes` and route-only provider boundaries used by startup/runtime discovery. Reload does not restart or mutate the runtime Service watch controller. The next complete runtime watch result may replace the reload-applied discovered route set normally.

If config loading, Kubernetes listing, discovery result construction, or route snapshot apply fails during reload, the previous active route snapshot and previous skipped Service metric values remain in place.

## Metrics And Observability

Metrics are optional and disabled by default. When enabled, `mc-gateway` exposes Prometheus text metrics for connection outcomes, route decisions, backend dials, fallback responses, reload results, route counts, config generation, active connections, durations, and Kubernetes discovery state.

Kubernetes discovery metrics are intentionally low-cardinality. Labels do not include namespace, Service name, host, backend, annotation value, Kubernetes resource version, or raw error text.

Structured JSON logs are emitted through Go `log/slog`.

## Fallback Responses

Fallback responses are opt-in:

- Status fallback can answer selected denied status pings.
- Status fallback can also answer backend status dial failures when `respondOnBackendFailure` is enabled.
- Login fallback can answer denied login starts with a disconnect packet.

Fallback responses are intentionally narrow and generic. Backend failure login fallback and maintenance fallback responses are not included in v0.1.0.

## Testing And Validation

Before publishing v0.1.0, follow the release readiness checklist in [v0.1.0 Release Readiness](../v0.1.0-readiness.md).

Required release checks include formatting, whitespace checks, Go tests, vet, race tests, Docker build smoke, and passing GitHub Actions. Manual smoke checks should cover static routing, unknown host behavior, status and login-start flows, `SIGHUP` reload preservation, Kubernetes discovery flows when a test cluster is available, and metrics endpoint sanity.

The optional real Minecraft server E2E workflow remains manual and requires explicit Minecraft EULA acceptance for the run.

## Known Limitations And Post-MVP Work

The following items do not block v0.1.0:

- Configurable Kubernetes watch retry/backoff settings.
- ClusterRole or all-namespaces Kubernetes discovery.
- Pod annotation discovery.
- EndpointSlice discovery.
- CRD route discovery.
- Informer-based Kubernetes discovery implementation.
- Scale-to-zero wake-up.
- Backend failure login fallback.
- UDP or extra TCP routing for mods such as Simple Voice Chat.
- REST or admin API.
- Web UI.

v0.1.0 should be treated as the first MVP release for the current gateway and namespace-scoped Service annotation discovery model, not as a general-purpose Kubernetes ingress controller or production-hardened Minecraft platform.

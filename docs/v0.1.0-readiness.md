# v0.1.0 Release Readiness

This checklist separates v0.1.0 release blockers from manual smoke checks and non-blocking post-MVP work.

v0.1.0 covers the current MVP behavior: static YAML routing, optional fallback responses, optional Prometheus metrics, graceful shutdown, `SIGHUP` reload, and namespace-scoped Kubernetes Service annotation discovery. Kubernetes discovery includes startup initial list, `SIGHUP` reload Service re-list, runtime watch updates, retry/backoff recovery, route-only provider boundaries, low-cardinality discovery metrics, and failure preservation.

## Required Release Checks

Run these before cutting a v0.1.0 tag:

```powershell
gofmt -l .
git diff --check
go test ./...
go vet ./...
go test -race ./...
docker build -t mc-gateway:dev .
```

The required GitHub Actions checks for the release branch or tag should also pass. At minimum, confirm the existing CI workflow passes, including formatting, Go tests, race tests, vet, and Docker build smoke.

## Manual Smoke Checks

Manual smoke checks are release confidence checks. They can use fake backends, local Docker backends, a real Minecraft server, or a disposable Kubernetes test cluster depending on what is available.

- Static YAML routing with at least two configured hostnames routes each hostname to the expected backend.
- Unknown host behavior matches both supported modes:
  - `unknownHostPolicy: "deny"` closes or denies an unknown host.
  - `unknownHostPolicy: "default"` routes an unknown host to `defaultRoute`.
- Status ping flow reaches a fake or real backend through the gateway and returns a status response.
- Login-start flow reaches a fake or real backend through the gateway and returns the expected first login-state response.
- `SIGHUP` static config reload applies a valid route change for new connections.
- `SIGHUP` static config reload preserves the old active snapshot when the replacement config is invalid.
- Kubernetes discovery startup initial list creates routes from annotated Services, if a test cluster is available.
- Kubernetes Service watch update applies a complete replacement discovered route snapshot, if a test cluster is available.
- Kubernetes `SIGHUP` reload Service re-list refreshes discovered routes without restarting the watch controller, if a test cluster is available.
- Metrics endpoint exposes Prometheus text and key gateway/Kubernetes metrics when `metrics.enabled: true`.

The optional real Minecraft server E2E workflow can be used as an additional manual smoke check after accepting the Minecraft EULA for that run. See [E2E](e2e.md).

## Non-Blocking Post-MVP Work

These items do not block v0.1.0. They are optional future work driven by operator needs or later product scope:

- Configurable Kubernetes watch retry/backoff settings.
- ClusterRole or all-namespaces Kubernetes discovery.
- Pod annotation discovery.
- EndpointSlice discovery.
- CRD route discovery.
- Informer-based Kubernetes discovery implementation.
- Scale-to-zero wake-up.
- Backend failure login fallback.
- UDP or extra TCP routing for mods such as Simple Voice Chat.
- REST or admin API.
- Web UI.
